Another fix release, three small ones. Nothing to update on your side.

## Links to an index page

A `Link` to an index page with no params,
or with an empty params tuple when every param is optional,
rendered an empty `href` instead of the folder's base:

~~~tsx
<Link to={["index"]}>Home</Link>
~~~

An empty `href` is a link to the current page.
So "Home" on any page other than home took you nowhere.

Most index routes have no params, so this was the common case, not an edge one.

And when the base was anything but `/`, the same link had a second problem:
the base was added twice. With pages at `/front`, "Home" pointed at `/front/front`.

Both fixed.

## dist/run.js without --host

Since `v0.6.0`, `kosmo.previewHost` in `package.json` holds a host and a port,
like `127.0.0.1:4558`.

`dist/run.js` falls back to it when no `--host` is given,
and it passed the whole pair to the server as the host.
There is no host called `127.0.0.1:4558`, so the server refused to start:

~~~sh
node dist/run.js -p 4556
# getaddrinfo ENOTFOUND 127.0.0.1:4558
~~~

That is the command the docs show for production, so it was worth a release on its own.

Now the fallback takes only the host from `previewHost`, and `-p` sets the port.

`kosmo preview` was never affected, since it always passes the host explicitly.

## /administrator is not under /admin

When a Vue folder renders on the server, its router strips the folder's base from the URL first.
The check was meant to ask "does this path start with `/admin/`?":

~~~ts
pathname.startsWith(join(base, "/"))
~~~

But `join` drops the trailing slash, so it really asked "does it start with `/admin`?".
And `/administrator` does.

So `/administrator` lost its first six characters and the router was handed `istrator`,
while rendering what should have been a plain 404 page.

It only bites a URL that shares the base's letters without being under it,
and only when the folder's SSR server runs on its own.
Behind `dist/run.js`, that URL never reaches the `/admin` folder in the first place.
Rare, but wrong since `v0.5.0`, when the router moved to the isomorphic `join`.

The check now matches the base itself or the base plus a slash, nothing in between.
